# 多源重置预测：实现与验收（2026-10-08）

## 范围

只调整“未来 48 小时官方自动重置概率”。个人额度、手动重置卡、自然周期刷新、窗口锚点及展开动效不变。完整、极简、菜单栏展开后共享同一个结果；不新增多百分比面板或下次检查倒计时。

首选为 [Codex Reset Monitor](https://codexreset.org/)，候补顺序为 [WhenReset](https://whenreset.app/api/)、[Codex Reset](https://codex-reset.com/developers)。首选基于[已记录的有限共同历史样本](qa-reset-forecast-source.md)；两家备用的先后是接入策略，不代表已证明的准确率排名。三个来源不能保证独立或持续运营，多源解决可用性，不能承诺提高准确率。

## 可执行规则

| 条件 | 处理 |
| --- | --- |
| 正常轮询 | 每轮并行检查到期来源，单源不早于上次请求完成后 5 分钟；手动/唤醒并发合并，不额外高频请求 |
| 当前来源健康 | 保持当前来源，数值直接取该来源，不计算平均值 |
| 当前来源一次连接失败 | 本轮立即选有效备用；无备用可用时显示未过期缓存，并标明缓存状态 |
| 连续 3 次连接失败 | 隔离为候补不可用，每 30 分钟探测一次 |
| 系统已明确本机断网 | 暂用有效缓存，不请求、不计入来源失败；联网恢复后按正常请求间隔检查，避免误把三家全部隔离 |
| 数据超过 6 小时、未来超过 5 分钟、结构/目标/概率异常 | 立即隔离，撤销该来源的缓存资格 |
| 概率数值没有变化 | 不据此判定停更；检查真实源数据时间与事件基准 |
| 遗漏交叉核对的重置 | 隔离并撤销缓存；需满足下方保守的事件规则 |
| 来源恢复 | 连续 2 次间隔 30 分钟的有效探测后恢复候选；中途失败重新计数；不会抢占仍健康的当前来源 |
| 全部不可用 | 只复用先前实际展示过、未过期且未被新数据否定的缓存，保留原来源和时间；否则明确显示不可用，不伪造 0% |
| 重启 | 恢复选源、各源健康/隔离状态和请求期限；未知来源、URL 不匹配、未知状态版本拒绝复用 |
| 系统时间倒退 | 未来/过期数据不可展示；重启恢复状态时限制异常请求期限，避免沿用错误的远期请求时间 |

正常前台文案为“未来 48 小时重置概率 XX%”和“多源自动选优 · 实验性预测”；缓存时副文案变为“暂用有效缓存 · 等待来源恢复”。原有说明内展示当前来源、选择理由及各源健康状态，不列出另外两家概率。简体、繁体、英文一致。

### 事件口径与不确定性

- 仅同口径的官方统一自动重置；不接入手动卡发放、个人 5 小时或周额度自然恢复预测。
- WhenReset 强制匹配公开 API 的产品/目标，`updated_at` 是预测计算时间，`data_as_of` 是输入账本时间；没有新事件时后者可不变。`hours_since_last` 只还原该源自己的基准，不作为官方完成证明。
- Monitor 与 Codex Reset 两个独立维护适配器的有效基准在 6 小时内相符时，才取更早者更新保守基准；落后该基准超过 6 小时的来源被排除。镜像同组不重复计票，WhenReset 的实验性账本不投票。单一来源的“新事件”不能剔除其他来源。
- 该规则仍依赖第三方正确标注已完成事件；缺少交叉证据时不会强行推断“已漏更”。它也不证明当前用户账号已重置，不改变本机验证状态。
- 不因没有实际发生重置就删除某个合法概率；预测是否准确需等待完整窗口和独立真值，再做同口径回测。

## 安全与持久化

公开只读 GET，无账号、密钥、Cookie 或本机信息上传。所有请求有限时，校验 HTTP、返回主机、内容类型及解析体积上限；不执行网页脚本。备用的辅助里程碑数据不可用时允许概率单独工作。

SQLite 新增单行 `reset_forecast_pool`，仅保存配置中 3 家的最新规范化快照和健康状态，以及最后展示值/来源/交叉核对基准。原来的 24 条展示快照仍有界保留。迁移只使用已验证的 Monitor 缓存，不把历史旧来源缓存冒充首选。缓存写入失败不会把成功的网络读取显示成来源失败。
