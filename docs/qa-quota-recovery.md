# 额度耗尽与手动重置：边界验收

日期：2026-09-03，发布前复测：2026-09-04。状态：纳入 `preview-0.2.1`。所有截图和零额度测试使用固定样本，不修改用户的真实额度或重置次数。

## 交互结果

极简警示修订：竖条/横条的红色只沿受限周额度的真实空轨道描边，取消画布外框与中央大感叹号。圆环使用真实圆形的内外描边，中心恢复原先留空的状态，不新增百分比或符号；单双环和各缩放尺寸都保持这一规则。陈旧/待确认使用琥珀色，菜单栏使用轻量重置/刷新符号。此修订不改变耗尽判定和手动重置资格。

仅在「周额度耗尽且有可用额外重置次数」时：完整额度显示 `Codex · 0%`，下面是「去手动重置」和跳转箭头。极简竖条、横条、圆环在原画布内显示红色警示，保留尺寸、拖动和开合锚点。菜单栏保留系统状态项，显示 `0%` 与操作。展开后第一块是持续可见的恢复说明和按钮，不依赖短暂通知才能找到入口。

5 小时额度单独耗尽不引导手动重置。没有可用次数时完全沿用原先的数值、倒计时、进度和布局，不增加耗尽卡片、警示边框或「查看用量设置」按钮。原有低额度/即将用尽阈值提醒保留，不添加可跳转重置的通知。

周额度耗尽且有次数时，数据过期、离线或到达周期刷新时间，入口改为「刷新」，避免根据旧数据建议使用重置。支出限制单独解释，不承诺额外重置能解除。周期以接口实际返回的 10080 分钟识别，不依赖主/次窗口名或用户是否显示 5 小时窗口。

## 已处理的边界

| 情况 | 结果 |
| --- | --- |
| 周额度为零，额外重置大于零 | 明确显示次数和操作入口，通知带用量设置操作 |
| 5 小时为零，周额度仍有剩余（包含隐藏 5 小时窗口） | 保持原样，不提示手动重置 |
| 仅返回 5 小时窗口且为零 | 保持原样，即使有重置次数也不提示手动重置 |
| 周额度为零但可用重置为零 | 保持原有布局和阈值提醒，不增加耗尽提示或跳转 |
| 5 小时、周额度同时为零且有次数 | 只按周额度提供入口，文案不把 5 小时列为重置原因 |
| 只有模型专项窗口为零 | 不冒充全部 Codex 额度耗尽，不触发全局手动重置提示 |
| 实际还剩 0.2% | 主要数值入口显示 `<1%`，不触发耗尽逻辑 |
| availableCount 为零，但历史详情仍有记录 | 服务端总数优先，不把历史记录当作可用次数 |
| 服务端返回总数，详情为空或截断 | 仍以总数显示，不按详情行数错误缩减 |
| 总数未知，详情缺失或状态未知/已用/撤销 | 不推断为零；没有可用证据时保持原有展示，不提供恢复入口 |
| 详情明确为 available，但总数未返回 | 用去重后的有效详情提供入口 |
| 重置在快照之后过期 | 从该快照总数扣除已知新过期项；全部过期后回到原有展示；不会二次扣除读取之前已过期的项 |
| 符合周额度和次数条件，但快照陈旧、离线或超过 330 秒 | 先刷新确认，不用缓存鼓励消耗次数；点击时重新判断 |
| 符合条件的周额度预计刷新时间已到 | 显示等待确认，优先检查真实额度 |
| 符合条件但 spendControlReached | 单独显示支出限制，不保证 reset 能恢复使用；不符合条件时不添加新卡片 |
| 反复轮询、应用重启、滑动重置锚点 | 同一次耗尽只提醒一次；缺失窗口不当作已恢复来重开提醒 |
| 明确恢复后再次耗尽 | 开始新的提醒周期 |
| 周额度恢复但 5 小时仍为零 | 周额度提醒周期正常结束，不被 5 小时状态阻塞 |
| 周额度仍为零，重置次数从零新增 | 新增恢复入口，并可开始新的提醒周期；未知次数不作为已恢复而反复提醒 |
| 系统通知被拒绝/关闭 | 不影响界面内的持续入口；不在未获授权时占用发送去重键 |
| 通知提交失败 | 释放当前通知键以便重试，不影响其他已发送键 |
| Codex 无法打开 | 提供明确的安装/启动和手动路径指引 |
| 真实读数恢复 | 自动退出耗尽展示，不因打开设置就提前假定恢复成功 |
| 旧按钮或通知被点击时，已无次数、周额度恢复或只有 5 小时耗尽 | 点击时重新校验，不再跳转手动重置 |
| 接口返回 NaN/Infinity | 拒绝异常额度值；不渲染成真实 0% |

## 跳转与安全边界

- 只导航至固定的 `codex://settings/usage`。链接不携带账号信息、凭证、重置 ID 或消费参数。
- 安装在本机的 Codex `26.831.21537` 路由包含设置页面与用量页面；其使用量上限重置区没有稳定的独立元素 ID，不能可靠构造 `#resets`。
- **尚未实现自动滚动/聚焦到重置按钮。** 界面清楚提示在「使用量上限重置 / Usage limit resets」区域手动确认，不声称已经定位。工具禁止操作 Codex 主界面，因此本轮没有真实界面跳转端到端验收，也没有使用替代 UI 自动化绕过此限制。
- 不调用 `account/rateLimitResetCredit/consume`。点击通知、完整额度、极简入口和恢复卡片都只导航或刷新。
- 不读取 auth.json、聊天内容、rollout 或浏览器 Cookie。新持久化数据仅包含耗尽周期的随机 ID 和额度窗口 ID，无账号标识。
- 计数语义依据 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)：`availableCount` 是权威总数，详情列表可缺失或截断。客户端展示不替代服务端最终资格检查。

- 前一次规则修订的 Address Sanitizer：恢复规则及原生窗口范围 30 项通过；不把它当作本次新增外观的内存安全验证。
- 本次极简外观 4 项测试通过：覆盖警示只作用于受限周额度、无次数不增加警示、待确认状态区分；原生像素断言另覆盖 36 种样式/单双额度/亮暗/缩放组合，保证警示不画到轨道外、圆环不出现切线或矩形角，且中心保持留空。
- 极简外观范围的 Address Sanitizer 4 项通过；重新截取本次受影响的 6 类情况，其余情况不受中心内容移除影响。24 种情况的 496 张原生截图文件尺寸与 SHA-256 校验通过。
- 三种语言、完整/菜单栏以及极简三种样式：共 15 种原生窗口组合。耗尽卡片下高度收敛到 180–330pt 范围；完整/极简在屏幕底部向上展开后收起，位置与之前相同。
- 另测「5 小时单独耗尽」「两个窗口均耗尽但无次数」× 3 语言 × 5 种形态/样式 × 5 小时开关开/关，共 60 种原生窗口组合。展开高度与没有恢复卡片的原有公式一致，收起回到原有位置。
- 本次检查了简中固定样本截图：无次数、5 小时耗尽均保留正常额度行，没有恢复卡片或多余空白。原先展示无次数警告卡片的测试图已移除；有效周额度入口预览保留。
- 导航测试使用注入的打开函数：验证唯一目标 URL、不携带伪造锚点、正确返回失败；没有进行真实重置。
- 发布配置 warnings-as-errors 编译和真实登录环境只读连通测试通过。`preview-0.2.1` 使用 Universal 2、ad-hoc 签名，仍不是已公证的正式发布包。

尚需人工验收：真实 Codex 设置跳转、系统通知实际送达/点击、VoiceOver、实际高频拖动与多显示器、同一套餐的账号切换。当前接口不提供账号身份变化证据，不能把测试账户切换等同于已覆盖的耗尽恢复周期。
