# 屏幕边缘展开回归

日期：2026-09-03。范围：完整额度、极简进度条的原位展开/收起；菜单栏不切换展开方向。

## 原因与处理

旧实现将向右下展开后的整个窗口限制在屏幕内，完整额度和窗口跟随还会提前为展开尺寸预留空间。靠底部时，这会向上推移收起组件；窗口的移动、缩放通知随后又从展开坐标更新收起位置。

新实现独立保存收起组件的屏幕矩形，在展开前选择向上/下、左/右的方向。液态遮罩和收起内容使用同一个方向与固定角；扩大原生画布不改变组件的屏幕位置。只有用户拖动及窗口跟随改变组件位置，展开避让不会写入位置记忆。

圆角由 SwiftUI 的同一视觉层处理，AppKit 宿主及框架层仅保留透明的矩形边界裁切。避免收起组件从小画布进入大画布时被不同的附加圆角再次裁切；不恢复原生矩形阴影。

## 回归范围

- 两种模式、四角、连续两轮开合：方向正确、画布不出屏幕、组件坐标不变、收起精确回原位。
- 负坐标显示器几何、超高/超宽内容的视口限制与方向锁定。
- 101 个动画进度点的遮罩角点与首尾矩形检查。
- 动画途中反向，任务/活动/提醒导致内容高度变化。
- 拖动向上展开的浮层，收起组件应用相同位移。
- 靠底位置保存、重启、切换形态、窗口跟随及移动显隐恢复。
- 明暗色原生截图：完整额度首帧的组件区域逐像素一致；极简条仅允许离屏栅格化至多四个通道各 3/255 的差异，坐标无容差。动画前后截图一致。
- 起始帧透明区域中不得出现额外不透明像素，以拦截矩形底色与白边回归。
- 现有额度显示、菜单栏、窗口跟随、协议、通知和本地缓存回归。
